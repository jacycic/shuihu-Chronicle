# shuihu-Chronicle
项目名称：水浒风云录---水浒传科普微信小程序;
技术栈：微信小程序、阿里云 OSS;
技术架构:微信小程序原生架构+第三方云服务;
安装微信开发者工具，在 config/index.js 中把资源地址替换成自己的即可运行;
团队信息:1梁文杰2.曾俊锋3.卢穗基

## 目录分层（视图与数据分离）

- `config/` 统一配置：OSS 资源地址、缓存键、页面路由、后端接口开关
- `data/` 静态数据：108 位好汉档案、剧情对话脚本、成就规则
- `services/` 数据服务层：页面唯一的数据入口
  - `request.js` 前后端边界，统一封装 `wx.request`
  - `heroService.js` 好汉档案与五维计算、测试匹配等领域逻辑
  - `achievementService.js` 成就规则计算与新解锁待提示队列
  - `progressService.js` 本地进度、成就、用户资料（按账号隔离，缓存读写收口）
  - `authService.js` 账号密码注册/登录、游客、进度同步（认证唯一边界）
  - `dialogService.js` 剧情脚本查询
  - `audioService.js` BGM 与音效
  - `friendService.js` 好友与私信云函数调用（需部署后启用）
- `cloudfunction/friend/` 好友 + 私信云函数（按登录账号隔离数据，身份由 openid 校验）
- `cloudfunction/auth/` 账号云函数（注册/登录 + 进度云同步，需部署后启用）
- `utils/tip.js` 把待提示成就交给页面上的 `globaltips` 组件依次弹出
- `pages/` 视图层：只负责渲染与交互，不直接读写缓存、静态数据或网络

## 接入后端

默认 `config.API.enabled = false`，全项目零网络请求、纯本地可用。
需要接后端时，在 `config/index.js` 填写 `baseURL` 并打开 `enabled`，
`heroService.refreshFromRemote()` 会在启动时从 `endpoints.heroes` 预热数据；
其余服务把 `read/write` 换成 `request.get/post` 即可，页面代码无需改动。
远程请求失败时自动回退本地数据，保证离线可用。

> 说明：`API.enabled` 控制静态数据的 REST 后端；`CLOUD.enabled` 控制好友功能的微信云开发，两者互不影响。

## 登录页与进度保存

启动首屏为 `pages/login/login`（`app.json` 的 `entryPagePath`）：账号密码登录 / 注册、
密码显示切换、游客进入；已登录时自动 `reLaunch` 回首页。个人中心可查看当前账号、
手动同步进度、退出登录。

进度不再是全机一份：`services/progressService.js` 按当前账号给缓存键加命名空间，
不同账号各有自己的收集进度、成就、头像与昵称；注册新账号时会继承本机已有旧进度，
退出后重新登录即可找回。登录态与账号表是全局键，不随账号隔离。

### 默认：本地账号（不需要服务器 / 数据库）

`config.AUTH.cloudEnabled = false`（默认）时零网络请求，账号表与进度都存在本机，
因此**换手机、卸载小程序、清理微信缓存后仍会丢失**。
本地密码用随机 salt + 轻量哈希避免明文存放，但这不能替代服务端鉴权。

### 要跨设备保存：部署账号云函数

**需要数据库，但不用自购服务器**，复用已有的微信云开发环境即可：

1. 云开发控制台 → 数据库 → 新建集合 `sh_accounts`，数据权限选「**所有用户不可读写**」。
   新版控制台没有「仅管理端可读写」这一项；控制台里的蓝字写明
   「云控制台和服务端始终有所有数据读写权限，以下配置仅对小程序端发起的请求有效」，
   所以选这一项就等于只允许云函数读写，前端无法直连数据库。
   文档以账号为 `_id`，存 `salt / passwordHash / openid / progress` 等字段。
2. 开发者工具左侧右键 `cloudfunction/auth` →「上传并部署：云端安装依赖」。
   建议把该云函数超时调到 10 秒（登录时 pbkdf2 有一定计算量）。
3. 打开 `config/index.js`，把 `AUTH.cloudEnabled` 改为 `true`；
   同时确保 `CLOUD.enabled = true` 且 `CLOUD.env` 已填环境 ID。
4. 重新编译：登录时拉取云端进度覆盖本机，退出登录或点「同步进度到云端」时上传；
   在另一台设备用同一账号密码登录即可看到相同进度。

> 从本地模式切换到云端时，原有本地账号不会自动迁移：用同一个账号名重新注册一次即可，
> 注册会把本机已有进度作为初始档上传；之后所有设备都用该账号登录。

云函数动作：`register`、`login`、`getProgress`、`saveProgress`。
账号在新设备登录后绑定该设备 openid，旧设备需重新登录才能再次写入进度。

### 安全约定

- 云端只存 pbkdf2 派生值与随机 salt，绝不存明文密码
- `saveProgress` / `getProgress` 用 `cloud.getWXContext().OPENID` 校验，前端不传 openid
- 集合权限「所有用户不可读写」，前端不直连数据库
- 本地模式的哈希只用于避免明文，不能当作鉴权；要真正安全请开启云同步

### 常见错误：云端服务异常 / -502001

`-502001` 是云数据库**操作失败**，常见两类原因：集合/环境不对，或进度字段写入方式不对
（报错里带 `Cannot create field 'xxx' in element {progress: null}`）。都不是前端代码问题。

**若报错含 `Cannot create field ... in element {progress: null}`**：云端账号的 `progress`
还是旧版写入的 `null`，云数据库把整体对象展开成 `progress.xxx` 点号路径时无法在
`null` 上创建子字段。云函数现已改用 `db.command.set` 整体替换该字段，并把新账号的
`progress` 初始化为 `{}`；重新部署 `cloudfunction/auth` 后再点一次同步即可，
**无需删除账号或集合**。

其余情况按顺序检查：

1. 云开发控制台 → 数据库 → 集合列表里是否有 `sh_accounts`
   （别和好友功能的 `sh_users` 混淆，名字必须完全一致）。
2. 确认集合所在的**环境 ID** 与 `config/index.js` 的 `CLOUD.env` 是同一个环境。
   控制台右上角可展开查看完整环境 ID；云函数用 `DYNAMIC_CURRENT_ENV`，
   会自动在 `CLOUD.env` 指向的环境里找集合，多环境时最容易建错地方。
   报错弹窗会带「云函数当前环境」，可直接和 `CLOUD.env` 对比。
3. 数据权限选「**所有用户不可读写**」。新版控制台只有
   「所有用户可读，仅创建者可读写 / 仅创建者可读写 / 所有用户可读 /
   所有用户不可读写 / 自定义安全规则」这几种；控制台蓝字说明
   「云控制台和服务端始终有所有数据读写权限，以下配置仅对小程序端发起的请求有效」，
   因此这一项**不会限制云函数**，选其它项反而会放开小程序端直连数据库的权限。
4. 右键 `cloudfunction/auth` →「上传并部署：云端安装依赖」，确认部署到上面同一个环境，
   然后重新编译；云开发控制台 → 云函数 → 日志里可看到具体数据库报错。
5. 集合若是报错之后才创建的，直接重新点一次「同步进度到云端」即可。
6. 若是「先在本地模式注册、后来才打开云同步」，云端还没有这个账号，
   用同一个账号名在登录页重新注册一次即可，本机进度会作为初始档上传。

若改用自建后端：把 `services/authService.js` 中的 `wx.cloud.callFunction`
换成 `services/request.js` 的 `post`，云函数业务逻辑可直接搬到 Node 服务；
页面与其它服务无需改动。

## 好友功能：需要云服务器或数据库吗？

**数据库必须有，但不需要自己买云服务器。**

好友关系是跨用户共享的数据，`wx.setStorageSync` 只存在自己手机上，
A 用户写入的内容 B 用户永远读不到，所以纯前端无法实现好友功能。

推荐**微信云开发**（Serverless）：云数据库 + 云函数，
不用买服务器、不用域名备案、不用配置 request 合法域名；
云函数通过 `cloud.getWXContext().OPENID` 拿到微信身份，再用 `sh_accounts.openid`
校验前端传来的账号，前端只调 `services/friendService.js`，不接触任何 openid。
云开发有免费额度，本项目之前也配置过云环境，可直接复用或新建。

### 部署步骤

1. 微信开发者工具 → 顶部「云开发」→ 开通并创建环境，复制**环境 ID**。
2. 打开 `config/index.js`：
   - `CLOUD.env` 填环境 ID（例：`cloud1-xxxxxxxx`）
   - `CLOUD.enabled` 改为 `true`
   - `AUTH.cloudEnabled` 保持 `true`（好友数据按登录账号隔离，依赖 `sh_accounts`）
3. 云开发控制台 → 数据库 → 新建 4 个集合：
   - `sh_users`：用户资料（昵称、头像、邀请码、收集数）
   - `sh_friend_requests`：好友申请
   - `sh_friendships`：好友关系
   - `sh_messages`：私信（`readAt: 0` 表示未读）
   - `sh_accounts` 不用手动建，按上面「登录页与进度保存」一节由 `auth` 云函数使用
   
   四个集合权限都选「**所有用户不可读写**」——云函数以管理员身份访问，
   前端不直连数据库，避免越权读取他人资料。
4. 开发者工具左侧分别右键 `cloudfunction/auth`、`cloudfunction/friend` →
   「上传并部署：云端安装依赖」（会按 `package.json` 安装 `wx-server-sdk`）。
   **改过任一云函数后都要重新部署**，否则新接口不会生效；
   建议在云开发控制台把两个云函数超时从默认 3 秒调到 10 秒。
5. 重新编译 → 个人中心 →「我的好友」。进入页面会自动生成 6 位邀请码，
   复制给朋友，对方在「添加好友」里输入即可发送申请；
   你同意后双方出现在好友列表，可查看彼此收集进度、删除好友。
   若双方互发申请则自动成为好友。
6. 点好友行的「聊天」进入私信页：好友页每 8 秒轮询未读消息并出**红点**，
   个人中心「我的好友」入口显示未读总数；进入聊天页自动标记已读、红点清零。
   删除好友会同时清除双方聊天记录。

> 好友、申请、私信按**登录账号**隔离：同一微信切换账号后互不可见，游客也有独立身份。
> 旧版本按 openid 存的好友数据**不会自动迁移**，升级后需重新添加好友
> （或在云开发控制台手动把旧记录的 `userA/userB` 改为 `u_<账号>`）。

### 同一设备不同账号的邀请码相同？

邀请码由云端按 `u_<账号>` 派生，账号不同结果必然不同。若实测相同，看好友页
「我的邀请码」下方的身份提示，它会直接指出原因：

1. 提示 **「friend 云函数仍是旧版」**：云端还在按微信号 openid 生成邀请码。
   在开发者工具右键 `cloudfunction/friend` →「上传并部署：云端安装依赖」，
   并确认部署环境与 `config.CLOUD.env` 是同一个；部署完重新编译再进好友页。
2. 提示 **「当前是游客身份」**：本地登录态没有账号名，请求被当成游客，
   而同一微信号的游客身份是固定的。退出后用账号密码重新登录。
3. 提示 **「云端账号与本地登录账号不一致」**：退出后重新登录当前账号。
4. 显示 **「当前身份：账号 xxx」** 时，切换账号后邀请码一定随之变化；
   若两个账号都显示同一账号名，说明登录态没有真正切换。

排查时可在云开发控制台查看 `sh_users`：新版文档 `_id` 形如 `u_<账号>`，
旧版是 openid 长串；两种同时存在不影响使用，但旧文档对应的邀请码已失效。

`CLOUD.enabled = false` 时不初始化云开发、不发任何网络请求，
好友页显示上面的开通引导，其余功能完全不受影响，可直接照常运行。

### 如果改用自建后端

需要准备：云服务器 + MySQL/PostgreSQL（对应 4 张表）+ 已备案的 HTTPS 域名
+ 小程序后台配置 request 合法域名 + 用 `wx.login` 的 code 调用
`code2session` 换取 openid 自行做登录鉴权。
代码上只需把 `services/friendService.js` 里的 `wx.cloud.callFunction`
换成 `services/request.js` 的 `get/post`，页面代码无需改动；
`cloudfunction/friend/index.js` 的业务逻辑可直接搬到 Node 服务里复用。

### 安全约定

- 微信身份只从云函数上下文取；前端传的 `account` 必须与 `sh_accounts.openid` 一致，
  否则拒绝访问，避免伪造他人账号
- 用户 ID 为 `u_<账号>`，游客为 `g_<openid 摘要>`，与旧版 openid 数据互不相通
- 对外只暴露邀请码与昵称等公开字段，不返回他人 openid 或账号名
- 好友关系与聊天都用排序后的用户 ID 对 `pairKey` 作唯一键，避免重复双向关系
- 发消息前校验双方已是好友；只有接收方能把消息标记为已读
- 头像只同步 http(s) 地址；`chooseAvatar` 的本地临时路径不可跨设备访问，
  此时前端用昵称首字圆形头像兜底
